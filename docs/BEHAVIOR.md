# Behavior and local development

## Route comparison

The directed taxi graph uses Dijkstra search with nonnegative costs. Distance mode minimizes total yards; Estimated time mode minimizes estimated seconds, including the walking leg to the departure master and the walking leg from arrival. The model also searches the other objective and bounded alternatives formed by removing individual flight edges. Results deduplicate matching itineraries, prefer current offered evidence on ties, and show at most three options. Distance is the default; choose Estimated time above route results or in settings for quickest estimated travel. Both controls save the same preference and replan displayed alternatives without replacing active navigation. Route quality precedes either ordering. These are bounded alternatives, not an exhaustive enumeration.

A category search filters by player faction, requested class/profession and typed query. Selected categories are combined with OR; class/profession subsets restrict only their own category. Empty categories mean All and ignore inactive subsets. Typed queries prioritize exact full NPC names and semantic role/type matches ahead of incidental names, with distance and stable ties inside each relevance tier. Prefixes and bounded edit-distance matching accept partial text and common typos. Route planning retains the best relevance tier before its distance/time shortlist, so an incidental nearby name cannot displace the requested service. Distance mode compares the twelve closest destination records. Time mode also includes up to twelve candidates ranked by running plus estimated arrival at reachable flight exits: one multi-source shortest-time pass supplies those arrival bounds. The union is at most 24 records and records whether the comparison was truncated. This bounded heuristic is not a global fastest-NPC guarantee. Individual NPC searches select a specific spawn. A preview From is recalculated from the player's current position before Go.

Static flight candidates require both endpoints to be observed as discovered for the current character and client build. Missing observations remain unknown and are excluded. Explicitly undiscovered endpoints can appear in separate darkened previews with a red label and disabled Go. Usable alternatives take priority; disabled previews fill only unused result slots. At an open flight master, an offered whole itinerary may include undiscovered fly-through nodes. Each offered hop must match a unique directed client path; ambiguous or unknown paths are rejected. Runtime slots are temporary and never saved as node IDs. Closing the taxi window invalidates the offer label, including copied cards.

While that window is open, the current master's offers override conflicting static departures. Offered full itineraries cannot silently acquire additional unoffered flight legs. After context closes, static candidates can be considered again with conditional availability. Confirmed boarding identity survives temporary missing positions independently of timing validity; recomputing previews does not overwrite an active flight's state.

Distances sum three-dimensional flight samples plus the short straight endpoint gaps to the listed taxi nodes. Paths with endpoint gaps over 150 yards, self loops, unresolved conditions/events or continent transitions are excluded. Only actual sampled flight segments are drawn; no line is invented between disjoint splines or across ground. All ground legs remain direct compass bearings, not traversable routes through terrain, interiors or barriers.

Soft ETA uses observable current/typical movement speed with a 7 yd/s fallback. Bearing-only ground time is `direct yards / speed × 1.35`: a fixed, bounded 35% allowance for bends, hills and obstacles. This general factor is uncalibrated, has no per-zone exceptions, adds nothing at zero distance and cannot establish that a ground connection is traversable. Physical distance is unchanged. The same helper supplies time ranking, candidate selection, leg summaries and remaining ETA; no second buffer is added. Verified/approximate corridor lengths would use their own distance without this bearing allowance, but none are currently supplied. Flights use a valid observed whole-itinerary duration when present; otherwise they use the explicitly uncalibrated 32 yd/s prior. Whole-itinerary measurements are never divided into invented per-hop times. Timing history is bounded, rejects large outliers, and is invalidated by loading, missing positions, death, teleportation, wrong flights and pause. Stops, detours, waiting and service interactions remain outside the estimate. The fastest estimate can therefore differ from the fastest real journey.

## Guidance and settings

The panel starts hidden on first use and when upgrading data without a saved visibility choice. Explicit Show/Hide (including the settings buttons and the expand/collapse binding's reveal action) persists per character across reloads and logins, independently of appearance profiles and client build changes. Startup, provider completion, world-entry, display, profile and placement updates respect that choice. Tuck remains a separate session action and does not change the saved Show/Hide choice. `/atcf show` reveals the panel; `/atcf hide` hides both the panel and its edge tab.

Modern and WoW Forever themes apply to the panel, navigation menu and shared SND options shell. Modern uses a thin border; Forever uses Blizzard dialog borders. Result selection remains distinct from hover, disabled actions fade, and open filters retain their hover edge. Explicit profile background/text colors override the theme for the navigation view; navigation arrows remain gold. Search fields and the inline route-order dropdown retain native search-border artwork.

Options use SND's Appearance, Navigation, Position and Profiles pages in a 640-by-500 shell. Short screens reduce the viewport and enable scrolling; narrow screens scale the shell to fit. Scrolling, page changes and display geometry changes dismiss menus and clear edit focus. Long dropdown captions retain their font size and abbreviate complete UTF-8 characters; the full name remains available in the menu and on hover. Settings and profile changes propagate to the navigation view after fonts settle. Color previews repaint without saving until accepted; cancellation or a profile change discards them.

The panel defaults to 240 logical pixels wide; the idle view is 139 pixels tall, including clearance for its resize grip. Existing custom widths survive upgrades; the former 304-pixel default migrates once to the narrower default. Search, selection, results and navigation expand it as needed. The funnel beside To opens the matching client's native checkbox menu with category OR selection, nested class/profession choices and All reset. Selecting class trainers initially chooses the player class. Active filters tint the funnel; selections persist independently in each profile. Empty searches distinguish unavailable NPC data, indexing and no matches. Clearing a field also clears its pending query, so blur or Enter cannot resurrect an old search.

Find routes selects the highlighted unfiltered destination and plans in one click. With category filters and no explicit destination, Compare matches compares the eligible matches. When selecting From, Use origin accepts that location without planning or replacing active navigation. Pending searches disable the action. Keyboard Enter retains its select-then-plan sequence. The crosshair restores the current origin.

A comparison waiting for NPC indexing automatically retries when indexing completes, showing routes or a final no-match result. Editing, choosing a location, searching again, Back or Stop cancels that waiting comparison. Completion preserves active navigation and the panel's visibility choice.

Route alternatives for one destination share its name and type/location above the list. Cards identify Walk or Walk + fly and show one total estimate with distance. Flight details label each Walk/Fly leg, retain planned leg times and wrap full station names below the Go button. Direct walking cards omit a duplicate itinerary. Comparisons across different destination records retain each card's destination identity. All matches remain scrollable; wrapped text determines row height, and a lower boundary separates overflowing results from the footer and resize grip. A visible footer action has twelve logical pixels of clearance below that boundary, included in the viewport and resize budget.

Search-match and route-card hover tooltips contain only "Travel time may vary based on terrain." They use small, muted text without repeating the destination, itinerary or provider details. The tooltip follows the selected font family at a fixed 11-pixel size, independent of panel scaling, and leaves other game tooltips unchanged.

Go collapses the panel without changing its width. Edit/routes expands it; Pause/Resume and Stop remain available. Opening an interaction with the active destination NPC completes the journey, even when paused or current coordinates are unavailable. Identity comes from the interaction unit's NPC ID, never the selected target or a preview destination. Flight-point destinations require a freshly reconciled taxi window at that final point; intermediate masters do not complete the journey. Death or being on a taxi prevents interaction completion. Completion and the manual nearby Done action show "Arrived!" for three seconds in the From/To view and clear journey/search state while preserving settings, filters, saved places and flight knowledge. Starting another search dismisses the notice immediately. Saved places also use proximity, map/floor identity and dwell time. Reload stops navigation and preserves settings and known-node observations; it does not resume a possibly stale journey. A client-build change clears taxi knowledge/timing, while player-recorded places are preserved with their old build and quarantined from search until re-recorded.

HUD and active map/minimap navigation use the supported client's up-facing player-arrow artwork in gold. Selected destinations preview as a crow before navigation starts. World pins retain their size across canvas zoom. Projection first reuses exact stored coordinates on the same map, then tries the native world transform; if that is unavailable, native parent-map rectangles can project a known city/zone point onto its ancestors. The fallback rejects unrelated maps, cyclic hierarchies and invalid coordinates rather than inventing a location.

Drag the header to move the panel, or snap near either screen edge. Drag the collapsed edge tab vertically to save a preferred screen-relative position shared by both edges; clicking reopens the panel near that position. Re-tucking and reloading preserve it, while Reset placement recenters it. Position lock prevents both panel and tab dragging. The return-arrow button returns to the previous view without stopping active navigation; the cog opens Settings, Save location, Lock, Tuck and Close. Tuck is a separate explicit menu action.

The bottom-right grip is available in every unlocked panel view. Width persists between 220 and 640 logical pixels; populated results also support height resizing, while idle, empty and compact navigation views retain their content-driven height. The panel and edge tab default to High frame layering at level 100; Low and Medium are available in settings. Options and menus remain above the panel. Settings also provide theme, font, font size, scale, background/text colors, position lock, independent map/minimap markers, placement reset, route ordering and per-character named profiles. Navigation gold is fixed; legacy accent values remain preserved in saved profiles. Duplicate, switch, copy and reset preserve character discovery/timing; destructive profile operations have inline confirmation and cancel. Legacy profile records retain their schema and migrations; unknown future records remain read-only. Geometry and filter changes commit atomically, and profile replacement cancels stale drag/resize callbacks. `/atcf`, `/atcf options` and `/atcf opts` open settings idempotently; `/atcf show` and `/atcf hide` control panel visibility. Expressway is requested from installed SharedMedia, never bundled. Flight selection and movement remain manual.

## Transmogrifier search

Transmogrifiers is a native checkbox in the existing filter menu. It shares profile persistence, category OR selection and All reset with the other services. Search accepts transmog, transmogrifier, transmogrifiers, transmogrification and NPC names. Semantic service matches retain priority over incidental names during route comparison.

The Forever service registry corrects missing provider roles for NPCs 270513, 270581 and 270582. Their positions, faction eligibility, phases and mobility still come from the read-only Forever QuestieDB API. Explicit provider service titles can identify additional transmogrifiers, including through raw English title fallback. The high NPC flag bit alone is not reliable role evidence in the installed Forever data. Missing positions or failed native map projection produce no destination. These records retain provider confidence and the existing bearing-only route and interaction arrival behavior.

Nearby stationary provider samples become one destination when their NPC identity, source area, world/UI map, floor, faction and phase agree and every pair is within five yards. The first original position and ID represent the group for both search and routing. Distant samples, different identities or contexts, and moving NPCs remain separate. Raw provider records stay unchanged. Fyrenz Vishonar and Spellweaver Thaldris each appear once in their eligible search results.

## Reproducing MONOLITH data

The exact-build workflow reads installed data through task-2's existing read-only extractor and pinned schemas. It does not alter task-2 or the game. Raw data and generated taxi payload remain under ignored `.work/`.

```text
python tools/extract_local.py
node tools/decode_tables.cjs
python tools/build_data.py
python tests/data_test.py
python tests/benchmark.py
python tests/measure_provider.py
python tests/package_test.py
python tools/package.py --local-data
```

The optional transport audit uses `python tools/extract_local.py --transport` and `node tools/decode_tables.cjs --transport`. Readable transport geometry does not establish passenger-stop connectivity. See `transport-audit.json` and the coverage document. Unknown schemas and encrypted records are rejected; no unavailable keys are guessed. Hotfix overlays are not applied. Public data rights and actual Forever smoke tests remain release gates.
